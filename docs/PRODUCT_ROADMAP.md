# ShuttleKit 装备推荐产品 · 架构与路线

> 目标：让用户更好了解羽毛球装备、选到适配自己的产品。  
> 定位：从「CV 技术工具箱」升级为「装备智能推荐产品」——这是产品/数据运营岗的优质作品集。

## 一、你的愿景 vs 现实约束（先说真话）

| 你的设想        | 现实约束                       | 结论                                                  |
| ----------- | -------------------------- | --------------------------------------------------- |
| 接入中羽在线数据    | 网站有反爬 + 服务条款限制，未经授权爬取有法律风险 | ❌ 不碰实时爬取，改为「人工整理公开评测 + 标注来源」                        |
| 实时更新评分/评价   | 实时=需要服务器+定时任务+反爬维护，个人项目负担重 | ⏸️ 后期再做，MVP 用「版本化数据集」                               |
| 纳入市面 95% 装备 | 全量数据采集是团队级工作量              | ✅ 先覆盖头部品牌（YONEX/VICTOR/LI-NING 等占 80% 销量），明确标注「样本库」 |
| AI 选择 / 智能体 | 完全可行，且有差异化                 | ✅ 核心卖点，优先做                                          |

**核心判断**：不要一上来做「实时爬虫平台」，那会让你卡在工程细节里翻车。  
正确路径：**先做一个「结构化装备库 + AI 推荐层」的 MVP**——数据是你整理的（标注来源、写清局限），AI 负责个性化匹配和解释。这反而更真实、更显产品思维。

## 二、产品架构（三层）

```
┌─────────────────────────────────────────┐
│  用户层：网站 / 小程序 / 对话机器人         │
│  （用户填：水平/预算/打法/部位 → 出推荐）   │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│  AI 推荐层（智能体）                        │
│  • 读取装备库 + 用户画像 → 自然语言推荐     │
│  • 解释「为什么适合你」+ 替代方案           │
│  • 可用 Coze/Dify(无代码) 或 LLM API 脚本  │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│  数据层：结构化装备库（JSON/Markdown）      │
│  • 3 类：球拍 / 鞋 / 球                    │
│  • 字段：品牌/型号/价格/参数/打法/评分/评价 │
│  • 来源标注 + 版本号 + 更新日期             │
└─────────────────────────────────────────┘
```

## 三、分阶段路线图

### Phase 1（现在做，MVP）

- [x] 扩展装备库：球拍 + 鞋 + 球 三类，统一 schema
- [x] 每类填充头部品牌代表型号（标注来源、评分、打法适配）
- [x] 升级推荐算法：按部位 + 水平 + 预算 + 打法匹配
- [x] AI 推荐脚本骨架（调用 LLM API，数据作上下文）
- [ ] 写进简历：「独立设计羽毛球装备推荐数据集与 AI 匹配逻辑」

### Phase 2（AI 智能体，1-2 周）

- [ ] 用 Coze/Dify 搭无代码对话机器人（拖拽，不用写代码）
- [ ] 或 Python 脚本接 通义/豆包 API，跑通端到端推荐
- [ ] 加「打法 quiz」引导用户填画像

### Phase 3（数据增强，后期）

- [ ] 邀请同学/球友贡献评测（UGC），扩大样本
- [ ] 用官方规格 + 公开评测文章做半自动更新
- [ ] 若需实时：评估合规爬取 / 官方 API（需授权）

## 四、对求职的价值

| 岗位    | 这个项目的加分点                     |
| ----- | ---------------------------- |
| 产品运营  | 完整的「用户画像→推荐」产品闭环，体现需求拆解能力    |
| 数据向运营 | 结构化数据集 + 指标体系（评分/匹配度），体现数据思维 |
| 功能测试  | 推荐逻辑可写测试用例（边界：预算为 0 / 打法为空）  |
